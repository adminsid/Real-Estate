# Hub Workspace login operations

The hub entry point is https://inside.primeamericarealestate.com/auth/workspace/start?return_to=%2Fdashboard. Public guidelines and `/brand-guide.md`, `/llms.txt`, and `/api/brand-guidelines` remain public. The hub's separate password, signup, account-admin, and password-reset APIs return 410. Manage accounts in Workspace `/user-management`.

The hub stores a five-minute browser login attempt and a one-hour session, both keyed by SHA-256 hashes. The one-time Workspace token is audience-, tenant-, and callback-bound. Secure, HttpOnly, host-only cookies bind the browser to its attempt and session; the callback redirects to a clean destination including the original fragment. Signing out revokes only the hub session. Disabled users and changed roles are reflected by a fresh Workspace membership check on each authenticated request.

Deploy prerequisites: provision the same random `BRAND_HUB_SSO_SECRET` as a Wrangler secret in `re-workspace` and `prime-america-hub`; never copy it into source or command arguments. Workspace `BRAND_HUB_TENANT_ID` and Hub `TENANT_ID` must both be `tenant_primeamerica`. Apply the additive Hub migration `016_workspace_login.sql`, including the session table that was absent in production. Deploy Workspace before the Hub. Hub `WORKSPACE_LOGIN_ENABLED=true` activates the new server flow. Do not rotate `INTERNAL_API_SECRET` for this rollout.

Verification: run tests, typecheck, and production build in both repositories. Workspace `worker/__tests__/hub-workspace-sso.test.ts` runs both applications' authentication logic against separate SQLite stores, verifying full handoff, preserved local profiles, current roles, revocation, expiry, logout, cross-origin destinations, replay, tenant/app/callback isolation, and conflicting identity mappings. The Hub also tests the Workspace-only login page and existing public guide functions.

Rollback: record each Worker's previous deployment version, then restore the prior Hub Worker and frontend together using Wrangler rollback if the new UI is unusable. Leave the additive tables and mappings in place to preserve profile associations. Workspace's scoped credential support may remain deployed. Disabling the Hub flag alone is not a complete UI rollback. The previous Hub deployment had a missing secret/session-table problem; reverting restores that limitation, so prefer correcting configuration when possible. Never delete profile mappings or change profile IDs as a login repair.

Live smoke checks require no impersonation: verify public guide URLs, Workspace-only login, redirect to Workspace with a browser state cookie, rejection of an invalid callback, and rejection of legacy password APIs. An actual user's signed-in browser is required to confirm production account access end to end.
