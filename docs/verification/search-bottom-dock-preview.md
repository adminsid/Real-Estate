# Results-first bottom controls — October 12, 2026

The consumer requested repeated utility filters and actions at the bottom, with visuals and results first. The private preview now defaults to a bottom dock. Search and filter controls open in a native dialog; view, sort, display settings, saved searches, page selection and map utilities open in a second dialog. Desktop provides layout and previous/next controls directly. Narrow screens provide Search & filters, Map/Homes, View & sort, and Save search. Comparison moves into the dock. Direct property links and photo interactions remain available on cards.

View & sort includes Controls position, allowing a switch back to the original top layout. The same DOM controls and existing search handlers are relocated; no duplicate search state, data requests or database changes are introduced. The choice is saved locally and in search/listing URLs. Results reserve space below the dock, focused controls scroll clear of it, and a skip link reaches search controls directly. Native dialogs also wrap first/last keyboard controls explicitly, restore the initiating action, support Escape, and retain invalid filter inputs and feedback.

Verification: all 492 tests in 63 suites passed; Workspace and both Worker type checks passed; Workspace and search production asset builds passed. Browser checks used actual CSS widths 320, 391, 768, 1367, 2560 and 844, including short landscape: no horizontal overflow, and dock stayed inside the viewport. The in-app browser was zoomed, so viewport overrides were calibrated against innerWidth. Checks covered top/bottom DOM restoration, immediate listing-link and full-search-link updates, live filtering, reversed-price rejection, saved-search feedback and restore focus, map tools, comparison, and keyboard wrap/Escape. Browser error logs were empty. Physical foldable hinges and iOS soft keyboards were not tested; segment CSS and safe-area/dynamic-viewport fallbacks are progressive enhancements.

Independent review found hidden saved-search feedback, preference loss through existing links, and reversed-price submission closing the dialog. All were fixed and re-reviewed with no remaining Required findings. Auto-height iframe embeds retain the existing top controls; a child-frame dock would otherwise sit at the bottom of the entire embedded document instead of the host viewport. No claim is made that bottom controls are measurably faster; that requires consumer task testing against the top-controls alternative.

Private preview deployment only. Public search, Access policy, feed ingestion and unrelated Workspace changes remain untouched.
